# Markdownプレビュー

## 要件・設計
- README.md等を開き、上部の「編集／Markdownプレビュー」で切り替える。タブは`.md`（大文字小文字不問）のファイルだけに表示。新規テキスト、通常テキスト、コードファイルでは非表示。MDファイルでの未保存本文の再プレビューは可能。
- `.md`ファイルは大文字小文字を区別せず、読み込み完了時に自動プレビュー。開く・履歴・起動時の再オープン・外部インテント・再読み込みの共通処理で判定。他の拡張子は編集表示。
- 原文のEditableは変更しない。保存・共有は引き続き原文。切り替えでは未保存状態、Undo、カーソル、編集スクロールを維持。新規作成で編集へ戻す。戻る操作はまず編集へ戻る。回転・テーマ変更では利用者が選んだモードをBundleで保持し、拡張子で上書きしない。
- CommonMark 0.22.0とGFM tables/strikethroughを利用し、見出し、強調、リスト、引用、コードブロック、水平線、表、取り消し線、リンクをHTML化。独自パーサーを避ける。
- 単一バックグラウンドスレッドで変換し、古い結果は世代番号で破棄。画面破棄時は処理をキャンセルしWebViewを破棄する。大容量ファイルの制約は既存と同じ。
- WebViewはJavaScript、DOM保存、ファイル、content URI、ネットワーク、画像読み込みを無効化。生HTMLはエスケープ、危険なURLは除去し、CSPでも制限する。HTTP/HTTPSリンクはタップと確認後だけ外部アプリへ渡す。
- 相対リンク・画像・HTML埋め込み・タスクリスト・数式・シンタックスハイライトは対象外。WebViewはMetaAppのXMLプレビューでは表示されない。ライト／ダーク配色は既存設定に合わせる。

## 検証
- 2026-11-06 最近使ったファイル／描画導線の再設計: 読込関数やActivity結果受信では表示モードの予約だけを行い、onPostResume以降のUIキューで一回描画。`PreviewLifecycle`を用いて復帰前・編集モード・重複要求で描画しない。onPause、編集へ切替、別ファイル読込で旧ジョブをキャンセルしWebViewを破棄。表示モードは保持し復帰時のみ再生成。変換用スレッドは全プレビュー共通の一つとし、キャンセル済み待機ジョブを削除する。
- 最近ファイル画面を開くときの別の危険箇所: onSaveInstanceStateが本文＋元本文＋最大50回分のUndoをBundleに格納し、EditTextも自動保存していた。AndroidのBinder転送上限を超え得る。保存データはアプリ専用noBackupFilesDirのAtomicFileへ退避し、OSにはUUIDトークンだけを渡す。EditText自動保存を無効にし独自復元へ統一。退避は状態保存完了前に必要なためonSaveInstanceState内で同期書込（巨大文書では遅延の可能性あり）。ファイル書込エラーは警告し、大きなBundleへフォールバックしない。復元不能なら警告して保存済み文書を読み直す。通常終了では対応する退避ファイルを削除。退避は共有／バックアップ対象にしない。
- 新しい状態テスト: 初回MD、停止中の履歴結果、選択せず履歴から戻る、MD→TXT、連打、100回の画面復帰。Android端末上の画面遷移・WebView・AtomicFile/Parcel復元・プロセス終了後復元は別途実機確認が必要。クラッシュログがないため、これらを報告されたクラッシュの確定原因とはしない。
- 2026-11-06 添付 `orchestrator-design-improvements.md` のクラッシュ調査: 原文を `app/src/test/resources/markdown/` に回帰テスト資料として保存（内容は表示データであり開発指示ではない）。ライト／ダーク各3回のHTML変換で例外なし。4つの表、フェンス付きツリー、末尾の節まで出力されることを確認。端末クラッシュログがないため報告された障害の原因確定・実機再現には至っていない。
- 表示経路の対策: WebView生成・HTML読込のRuntimeExceptionを記録してエラー表示。API26以上のWebView描画プロセス終了はonRenderProcessGoneで処理し、壊れたWebViewを破棄して本文を保持。次回プレビュー選択でWebViewを作り直す。変換失敗も例外を記録する。ログにはMarkdown本文・ファイル名・URIを意図的に追加しない。
- 起動時はload()で描画後にonCreate末尾で再描画していたため二重処理を除去。配色処理はプレビュー配下を走査せず、WebView内部ビューへ干渉しない。
- 未確認: 実機での添付ファイル読み込み、WebView生成障害・描画プロセス終了からの回復、画面回転、ライト／ダーク変更。再発時はAndroidのクラッシュログ（例外名とスタックトレース）、端末／Android／WebViewバージョンを利用者に依頼する。構文変換テストのみで端末クラッシュ解決と断定しない。
- 枠線図の崩れを再現: 上辺（┌─┐）、縦線、空行、4スペースで字下げした下辺を持つHUD図は、通常段落とインデントコードに分割される。ツリー専用の段落補正では上辺・全体範囲を検出できなかった。修正前に再現テストが失敗することを確認。
- 枠線図はMarkdownのブロック分割前に上辺から下辺まで検出し、表示用コピー上で一つのコードフェンスに包む。空行、字下げ、内部区切り線を保持し、横スクロール表示。細線・太線・二重線に対応。既存のコードフェンス・HTMLブロック・引用・リストは除外し、閉じていない図や途中の通常文章は取り込まない。原文・保存データは変更しない。
- 回帰テスト: 空行＋字下げのHUD図、既存コード／引用／リスト、二重線＋CRLF＋HTMLエスケープ、閉じていない図、文章を挟む複数の図。スクリーンショットは参照したがgun2.md原文は未提供のため、実ファイル一致の検証と実機表示は利用者確認が必要。
- コードフェンスのないツリー図も互換表示する。トップレベル段落の行頭にある├─／└─（太線も可）と縦線の連続行、および直前のルート行をコードブロックとして表示。元ソースの改行・字下げを保持して横スクロールする。通常文章の改行、既存コード、リスト／引用の解釈は変更しない。元ファイル自体に改行がない場合の階層推測は行わない。
- ツリー表示の回帰テスト: audioディレクトリ、Node構造と隣接文章、既存コード・通常文章の保持、CRLFとHTMLのエスケープ。端末では該当MDでツリーの整列と横スクロールを確認する。
- MarkdownRendererTest: 日本語見出し、リスト、引用、コード、強調、表、取り消し線、リンク、生HTML、危険URL、空本文、未完コード、原文保持を確認。
- 手動確認（端末で実施が必要）: README.mdを開く→プレビュー→編集→未保存変更→再プレビュー。原文・未保存表示・Undo・選択・スクロール保持を確認。
- 回転、設定でのテーマ変更、戻る、新規作成、別ファイル読み込み、読み取り専用、空本文を確認。
- 表と長いコードの横スクロール、外部リンクの確認／キャンセル、相対リンクの拒否、画像非取得を確認。
