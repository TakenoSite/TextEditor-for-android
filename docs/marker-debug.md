# 折り返し時の改行記号の位置ずれ調査

## 原因
- `WhitespaceEditText.onDraw` はViewのスクロール済みCanvasで実行されるにもかかわらず、記号描画時にさらに `-scrollX/-scrollY` を加えていた。折り返しで本文高さが増えて縦スクロールが始まると、本文と記号の差がスクロール量に応じて大きくなる。
- クリップ矩形は逆にスクロール量を含まない固定座標だったため、スクロールした記号が欠ける場合もあった。
- 改行文字の幅は0であり、折り返し行の右端には記号の幅が確保されていなかった。
- 横スクロール状態から折り返しをONにした際に、以前のscrollXが残る可能性もあった。

## 修正
- Android 14のAOSP `TextView.onDraw` の描画方式と照合。記号には本文と同じLayoutのXと行baselineを使い、スクロール量を二重に引かない。`getLineBounds`からパディング/縦Gravityの補正を取得する。
- クリップ矩形はスクロール済みコンテンツ座標で作る。
- 改行記号ONのときだけ右側に表示幅を予約し、記号はその余白内まで描画する。文字サイズ変更時にも幅を再計算。
- 折り返しONで横スクロール位置を0へ戻す。
- 画面上の折り返し行は改行コードの種類のインデックスを進めず、実データ中の `\n` でのみ進める。記号は実改行だけに表示。

## テスト
- 単体テスト: スクロール済み座標とクリップ、折り返し行/空行の実改行インデックス、混在CRLF/LFの記号、Layout由来の可変baseline。
- 手動確認: 長い日本語/英語行＋CRLF/LF混在、折り返しON/OFF、上下スクロール、横スクロール後の折り返しON、25/100/200/400%の拡大率、空行、行間変更で本文末尾と記号が同じ行にあることを確認する。
- 実機での描画再現・目視確認は未実施。単体テストは座標計算の回帰を確認するもので、Android Layoutそのものの描画を検証したものではない。
- `./gradlew assembleDebug testDebugUnitTest lintDebug --offline` 成功。新規5件を含む全25件の単体テストが成功し、Lintはエラーなし（既存の警告等は残る）。
