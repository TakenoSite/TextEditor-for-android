# 最近使用したファイル

## 要件・基本設計
- ハンバーガーメニューの同名項目から専用ページを開く。
- 実際に開けたファイルのURI・表示名・日時を端末内に保存して、新しい順に並べる。本文そのものは履歴に保存しない。
- 選択したURIを編集画面へ返して開く。未保存の編集があれば従来の破棄確認を行う。ページから戻るだけでは編集中の内容を変更しない。

## 詳細設計
- ユーザーの指定により全ファイルアクセス方式も追加。ローカルパスを履歴へ保持し、許可後はパスから読み書きする。OS許可画面への導線・解決できる提供元・制約は `all-files-access.md` を参照。
- 非公開の `RecentFilesActivity` と `activity_recent_files.xml`。名前/リンク/日時をカード型リストに表示し、ライト/ダークに対応。
- `RecentFilesStore` がアプリ専用SharedPreferencesへJSONを保存。URI単位で重複を排除し、再度開いた際は最上部へ移す。同名でもURIが違えば別項目。保存成功時も新規保存したURIを履歴へ記録する。最大100件。
- 各ロード/保存が成功してから記録し、読めなかったリンクは最終使用日時を更新しない。
- 通常の「開く」も「開く (SAF)」もOpenDocumentを使用。一時権限しか取得できないGetContentを廃止。読み書きの永続権限を取得し、読み取り専用なら読み込み権限だけで再試行する。保存した新規URIにも同じ処理を適用。外部アプリの一時的なVIEW権限までは勝手に永続化できないため、履歴の失敗時に「再選択」操作を提供する。
- 再選択はACTION_OPEN_DOCUMENT。Android 8以降では失効したURIを初期位置のヒントに設定。キャンセル・読み込み失敗なら既存の本文と履歴は維持し、成功してURIが変わったときのみ古い履歴リンクを削除する。実ファイルは削除しない。永続権限を取得できない提供元ではその旨を通知する。権限の迂回や端末全体のファイル探索はしない。
- ファイル移動/削除は追跡しない。内容はURIから毎回読み直すため、履歴はバックアップではない。

## 確認
- 単体テスト: 重複排除、再オープン時の先頭移動と名前更新、同名別URI、100件上限、初回記録。
- 手動手順: 履歴なし→SAFでA/Bを開く→履歴でB/Aの順序確認→Aを選ぶ→再度履歴でA/Bの順序確認→アプリ再起動→Aを再開。未保存時の破棄/キャンセル、戻るだけ、削除したファイルのエラー、ダークテーマも確認する。
