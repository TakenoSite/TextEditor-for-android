# 行番号ずれと縦慣性スクロール

## 原因と方針
- 旧行番号は本文とは別のTextViewの改行リストだった。本文内のフォールバックフォント（▼、絵文字など）の行高や折り返しを反映できず、長文でずれが蓄積する。また5,000行で表示を打ち切っていた。
- `LineNumberView`は本文Layoutのbaseline・padding・scrollYを直接使う。論理行（LF区切り）先頭のみ番号を描き、折り返し継続行は空欄。表示中の行のみ描画し、行番号上限は廃止。本文は変更しない。
- 改行位置は編集時にキャッシュし、スクロール描画では二分探索で対応。特殊文字のフォント高さを固定して切り落とす修正は行わない。
- 縦フリック終了時にOverScrollerで減速。再タッチ、複数指操作、折り返し変更、View破棄時に停止。横主体のフリック、長押し／選択中には新たな慣性を開始しない。通常の編集・選択・ピンチ動作は維持する。
