# すべてのファイルへのアクセス

## 合意・権限
- ユーザーの明示的な希望により、履歴再オープンでMANAGE_EXTERNAL_STORAGEを使う方式を追加。
- Android 11以降: Manifestに権限を宣言し、タップ操作からアプリ個別の「すべてのファイルへのアクセス」設定を開く。アプリが許可を自動付与したり、OSの制約を回避したりすることはない。
- Android 7–10: READ/WRITE_EXTERNAL_STORAGEのランタイム許可。Android 10用にrequestLegacyExternalStorageを指定。
- 履歴ページに未許可時の許可操作、設定に「ファイルアクセス」カテゴリー、履歴の読み込みエラー通知にも許可操作を用意。許可後の実状態をEnvironment/PackageManagerで確認する。拒否してもSAF経由の既存機能は継続して利用できる。

## ファイルの読み書き
- 履歴にはURIに加えて、判定できた共有ストレージ上のパスを保存。旧履歴は再オープン時にパスを解決して更新。
- ExternalStorageのprimary/home/外部ボリューム、Downloadsのraw URI、提供元が返す_data、許可後のMediaStore参照からパスを解決。端末内のファイルを名前で全探索する処理は行わない。
- 全ファイル権限があればローカルパスを使って読み書きする。読み込み時にローカルから開けなければ元URIも試す。書き込みは既存の書けるローカルファイルがある場合に限り直接行い、それ以外は従来のURI方式を使う。別名保存の際は前のファイルのパスを引き継がない。
- パスの変換では共有ストレージのルートを限定し、相対パスの..、不正なボリューム、NUL等を拒否する。
- クラウドURI/不透明な提供元URIはローカルパスへ変換できない場合があるため、永続SAF権限と再選択を引き続き使用する。Android/data等のOS保護領域や他アプリの内部データまで開けるとは保証しない。ファイルの移動/削除は追跡しない。
- Google Play公開時は全ファイル権限に関する申告・ポリシー適合の別途確認が必要。現作業では公開しない。

## 確認手順
1. 履歴ページの許可操作→OS設定で許可→アプリに戻り許可操作が消えること。
2. Download/Documentsのテキストを開く→アプリ終了・再起動→履歴から再開・編集・上書き。
3. 旧URI履歴から同じ操作を確認。外部SDカード、Downloads提供元、MediaStore由来のファイルも確認。
4. 許可しない/許可を取り消した場合、SAFで選択したファイルは従来通り開け、失効URIには許可/再選択が出ること。
5. 別名保存で元ファイルを上書きしないこと、クラウドや保護領域の失敗が適切に処理されること。
